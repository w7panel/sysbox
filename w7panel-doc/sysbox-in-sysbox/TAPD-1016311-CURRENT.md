# 1016311：sysbox-fs 调度与缓存（当前方案）

> 2026-11-19 更新。TAPD 1016311 原正文及伪代码为废弃设计稿；以本文和实际发布验收记录为准。

## 已实现

- `/proc/loadavg` 按视图维持独立的 5 秒 EWMA 采样状态，所有者退出后停止并清理。瞬时资源文件按请求视图使用短 TTL 快照，并合并同键并发未命中；容器注销时清理所属状态。
- 全局原始数据可有限缓存；最终输出仍必须按每次请求的 cgroup 和 PID namespace 实时确定视图。runc 登记的身份仅作为种子，不能用 L1 init 快照直接替代内层请求者解析。
- `/proc/swaps` 最终输出含请求者 cgroup 的 swap 用量，不能作为全局静态输出缓存。已采用按请求视图的短 TTL 快照，保证分段读取一致。
- cgroup v2 请求路径和视图键已减少无用解析与分配。键生成本地微基准约 32→21 ns/次；该数字不代表整机 sysbox-fs CPU 已下降。

## 不采用与未完成

- 不采用容器 TTL 注解；不把所有 handler 改为统一 `procCache`/`RWMutex`，也不把 cpuinfo、swaps 等最终输出一概做全局长 TTL 缓存。缓存边界按原始数据和请求视图区分。
- 不采用旧稿中的 runc 创建期完整 uptime/loadavg/cpuinfo 最终输出种子及 runc 下发透传/模拟文件名单。短 TTL 种子可能首读前过期，外层 init 种子不能代表不同 cgroup/PID namespace 的请求者；名单会与现有 FS handler 分流重复，还需扩大跨组件协议。现有 handler 注册和实时请求者解析继续负责分流。
- L2 `sysbox-runc-lite` 不启动、登记或依赖独立 sysbox-fs/mgr；其 `/proc` 走既有挂载与默认运行时行为，部分读取可碰到继承的 L1 FUSE 挂载，不增加 L2 专用虚拟化逻辑。

## 验收状态

L0/L2 功能回归已通过。先前 v40 约 26 秒、v47 约 56–59 秒的 16,000 次读取对照使用 shell 内建 read 读取首行；strace 证实它逐字节调用 read(…, 1)，把文件行长放大成大量 FUSE 请求。因此旧数值只代表该特定逐字节压力方式，不能据此判定常规缓冲读取的 CPU 降耗目标。请求者 cgroup/PID namespace 仍须逐请求实时解析，不能复用外层 init 快照。v40 与当前版本在正确缓冲读取口径下的同场 A/B 尚待补测。

此前仅为 `/proc/loadavg` 读取 PID namespace 的实验也使用逐字节读法；旧基线 56.76 秒、候选 55.16/56.60 秒只说明该压力方式下收益不稳定，实验代码已撤回。

此前尝试将每请求 cgroup 读取改为固定缓冲 open/read：同源原实现 54.24 秒、候选 54.17/51.89 秒，同样基于逐字节压力方式，不能证明常规缓冲读取收益；实验代码已撤回。切换服务后首次采样发生在 FUSE 挂载恢复前，失败样本已作废。

2026-11-19 测量口径更正：旧脚本用 shell 内建 read 读首行，逐字节触发 FUSE 请求；swaps 44.74/44.36 秒与其它文件的排名由此严重偏置，原“swaps 最贵”的结论作废。改用单个静态进程，每次 open 后以 8 KiB 缓冲读完整文件至 EOF，再 close；8 Pod/16 容器，每项 4,000 次全部成功。原 v47 的 FS CPU 秒：swaps 1.75、meminfo 1.67、stat 1.65、loadavg 1.79、cpuinfo 1.73、uptime 1.74；当前源码同源构建分别为 1.63、1.56、1.69、1.57、1.60、1.70。六项差异很小，不能认定 swaps 是热点；宿主负载波动下也不宜细排。测试后已恢复原 v47、Deployment 缩至 0，四项服务 active、节点 Ready。该隔离 VM 结果仍不代表 218 业务或正式发布验收。
